# ADR implementation status

Audit basis: the working tree on top of `d549644`, inspected 2026-08-25. This
ledger classifies the scope each ADR currently accepts. It does not turn a
capability that an ADR explicitly leaves for a later decision into a closure
gap. Evidence below names the primary implementation and the narrowest useful
test or gate. The broad hosted gate and all four QEMU platform suites were
rerun after ADR 0030.

## Summary

| Classification | Count | ADRs |
| --- | ---: | --- |
| Implemented | 28 | 0001–0005, 0007–0008, 0010–0030 |
| Superseded + implemented | 1 | 0006 |
| Direction / deferred by explicit scope | 1 | 0009 |

The accepted ADR closure set has no remaining implementation gap. Physical
machines, embedded/no-MMU compositions, e1000, GPU, audio, broad filesystem
writers, and real cloud-provider drivers/import paths are explicitly later
features.

## Closure conclusion

All accepted current-scope ADR contracts are implemented, including ADR 0016
Phase B, shell-launched KEX commands, and the owned application datagram,
read-only filesystem, atomic mutation, monotonic timer, and typed diagnostics
services, plus capability-separated typed network observation, DHCP, and ICMP
echo. ADR 0030 removes the privileged ordinary-command fallback, leaving only
three shell intrinsics. TCP remains a separate bounded state-machine, timer,
ownership, backpressure, teardown, and adversarial-test decision.
